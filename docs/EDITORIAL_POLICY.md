# Editorial policy · Stage 5B
## v1.0 · 11.08.2026

### 1. Зачем нужен отдельный слой

`data/editorial.json` — внутренний editorial control plane. Он не входит в `dist/app-data.json` и не должен читаться публичными Tilda-модулями.

Публичная история «Жизнь книги онлайн» продолжает использовать только подтвержденные `publishedAt`, `updatedAt` и `changeSummary`.

### 2. reviewedAt

`reviewedAt` означает только одно: материал фактически просмотрен редактором на актуальность.

Запрещено:
- ставить `reviewedAt` массово «для старта»;
- использовать GitHub commit как reviewedAt;
- менять `updatedAt`, если содержательно материал не редактировался.

### 3. Классы

- `rapid` — 90 дней: ИИ, платформы, регулирование, CommTech/MarTech, текущие исследования, развивающиеся методические контуры.
- `regular` — 180 дней: гайды, чек-листы, прикладные модели, рабочие кейсы.
- `evergreen` — 365 дней: устойчивые принципы, ретроспективы, фундаментальные профессиональные рамки.

Baseline-классификация — рабочая версия. После первой редакционной сессии класс отдельного материала можно изменить аргументированно.

### 4. Status и Priority — разные вещи

**Status** отвечает: «наступила ли календарная дата проверки?»

- `current`
- `review_soon`
- `review_due`
- `overdue`

**Priority** отвечает: «насколько срочно редактору брать это в работу?»

- **P0** — rapid, уже `review_due/overdue`;
- **P1** — regular `review_due/overdue`, любой `review_soon`, evergreen `overdue`;
- **P2** — остальное.

Это позволяет не объявлять десятки legacy-материалов одинаково срочными только потому, что это первый запуск freshness-control.

### 5. После проверки

Если материал актуален:
- правим только `reviewedAt`.

Если материал содержательно обновлен:
- `updatedAt` и `changeSummary` в `data/materials.json`;
- `reviewedAt` в `data/editorial.json`.

Если материал утратил смысл / ссылка должна быть закрыта:
- отдельное решение по public `status`.

### 6. Legacy publishedAt

Для старых QR-материалов `publishedAt` используется как baseline редакционной хронологии до первой реальной проверки. Он не трактуется Stage 5B как архивное доказательство точного дня первой публикации Tilda.

### 7. Что Stage 5B не делает

- не строит CMS;
- не создает личный кабинет редактора;
- не меняет интерфейс Navigator;
- не отправляет editorial-данные пользователю;
- не создает искусственные публичные обновления.
